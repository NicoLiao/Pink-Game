# LoveShot — Project Guide

Cute, chaotic, pink top-down 2D arena shooter (Unity 6000.6.7f1, URP 2D, C#). **Online multiplayer only:** private Relay
rooms, 2–4 humans, free-for-all (Pink/Berry/Coral/Blush, all shades of pink told apart by symbol: heart/star/flower/diamond),
180s, no AI. Players shoot love projectiles to convert neutral NPCs and steal each other's; players can themselves be converted
to another team (taking their NPCs along). Four weapons with timed pickups, special NPCs (Drama Queen, Celebrity, Cupid, Hugger),
team scores (Celebrity = 3 points). Players are never eliminated, only converted.
The former single-player mode (Pink vs a Blue AI mini-boss) was removed on 2026-10-30; it is still in git commit `ce98e98`.

## Session protocol
- **At the start of a session:** read `GAME_DESIGN.md` (what we agreed) and `PROGRESS.md` (what exists, what's verified, known bugs, next steps).
- **Before major changes and before context compaction:** update `PROGRESS.md` (and `GAME_DESIGN.md` if a design decision changed).
- Only record a feature as done or verified once it actually is. Keep "automated check passed" separate from "needs the user's playtest".
- Work one phase or feature at a time, and only start the next one when the user asks.

## Architecture (`Assets/Scripts`, namespace `LoveShot`)
- **Core:** `Mover` (movement, dash, `SpeedMultiplier`, `DashDistance`), `Steering` (wall avoidance, line of sight), `AimIndicator`, `TeamStyle` (team symbol sprites).
- **Skills:** `Skill` base class (name, key, icon, cooldown, `TryActivate(direction)`); `NetDashSkill` (dash instantly on the owner, host confirms the cooldown). `SkillBarUI` shows one `SkillSlotUI` per `Skill` on the bound player. A new ability = a new `Skill` subclass.
- **UI:** `MainMenu` (page switching, `Quit()`; page 0 = Host Game / Join Game / Quit, page 1 = room code), `UIFloat`, `ButtonBounce`, `AimCursor` (on the arena HUD canvas; sets the generated crosshair, restores the system cursor on unload).
- **Effects:** `HeartBurst`, `HeartRing` (area shockwave), `FloatingText` ("+1"), `CameraShake` (shakes around `BasePosition`), `SquashStretch` (hop/lean/breathe/squish on a character's "Rig" pivot; reads motion from the transform, so it works on networked copies; `Kick()` for recoil), `ProjectileGlow` (glow + trail in the projectile's color).
- **Multiplayer (`Scripts/Multiplayer`, namespace `LoveShot.Multiplayer`; Netcode for GameObjects 2.13 + Multiplayer Services 2.4 sessions over Relay; host-authoritative):**
  - `MPConnection` (on the NetworkManager prefab, created by `MultiplayerMenu` on demand, destroyed when the session closes): UGS anonymous sign-in (one auth profile per process), `HostAsync`/`JoinAsync` (return an error string or null), connection approval (max players, no join during a match), disconnect → main menu with `PendingMessage`, `Close()`.
  - `MPLobby` (spawned by the host, DontDestroyOnLoad, lives for the whole session): `NetworkList<MPPlayerInfo>` (clientId, slot = team = color, name), phase, room code; `StartMatch`/`ReturnToLobby` (host) load scenes through Netcode's SceneManager.
  - `MPMatch` (spawned by `MPArenaBootstrap` on the host in MPArena): spawns players/NPCs once, phases Waiting → Countdown → Playing → Ended on server time (`MPMatch.InProgress` gates gameplay), `NetworkList<MPScore>`, `Ranking()`, and projectile relay (host simulates `MPProjectile`, clients get visual copies via RPC; hits processed once on the host).
  - `MPPlayer`: **owner-driven movement** (the owner runs `Mover` itself; NetworkTransform in Owner authority) with a host-side movement budget that snaps back impossible moves (`CorrectPositionRpc`). Dash starts at once on the owner (`TryDash`), the host confirms the cooldown (`RequestDashRpc`). Shots: the owner fires on its own cooldown, shows predicted projectiles immediately (`MPMatch.PredictWeapon`) and sends `ShootRpc`; the host validates rate, origin, lovestruck, then fires the authoritative projectiles whose ids take over the predicted copies (`PredictKey`), or `RejectShotRpc` removes them. Aim is an owner-writable NetworkVariable. The host still decides hits, lovestruck, conversion, weapons and scores.
  - `MPNpc`: host-only AI with virtual hooks (`Wander`/`Follow`/`UpdateCombat`/`TargetScore`/`Shot`/`Fire`/`OnTeamChanged`); subclasses in `Multiplayer/Npcs` (`MPDramaQueenNpc`, `MPCupidNpc`, `MPHuggerNpc`; the Celebrity is a plain `MPNpc` with `scoreValue` 3). Visuals: `MPPlayerVisuals`, `MPNpcVisuals` (team badge), `MPCaptureBar` (love meter over any character), `MPNpcFlair` (special-NPC animations). UI: `MultiplayerMenu`, `MPLobbyUI`, `MPHUD` (timer, team leaderboard, results), `MPStatusHUD`, `MPWeaponHUD`, `MPFeed`. Camera: `MPFollowCamera` (local only).
  - **Allegiance model:** `MPCapture` (on NPCs *and* players) is the single source of truth: `Owner` = current team, `PersonalOwner` = player slot credited with it, plus capturer/progress (rules in `GAME_DESIGN.md` §10). `MPPlayer.Slot` is permanent identity (name, identity color, `MPPlayer.ForSlot`); `MPPlayer.Team` = its capture owner. NPCs follow `ForSlot(PersonalOwner)`. Every hit goes through `MPMatch.ApplyLove(target, creditSlot, power, fromPlayer)`, which uses the credited player's team *at impact*. Converting a player (`MPPlayer.ServerReceiveLove` → `ServerOnConverted`) starts 3s immunity and moves their personal NPCs. `MPMatch.UpdateScores` (host, 5/s) builds per-team `MPScore` (points, NPCs) for teams with players and neutralizes orphaned NPCs.
  - **Weapons:** `MPWeapon` ScriptableObjects in `Assets/Settings/Weapons` (index 0 = Default Gun, on `MPMatch.weapons`); the builder creates them **only if missing**, so tune the assets. `MPShot` describes one projectile (style, speed, power, lifetime, scale, bounces, explosion). `MPProjectile` finds walls with a swept circle cast (identical ricochets on host and client copies). `MPMatch.FireWeapon/Fire/Explode`. Pickups: `MPWeaponPickup` (networked; host decides the single collector) spawned by `MPPickupSpawner` (on the MPMatch prefab, host only). NPC spawn table: `MPMatch.npcTypes` (`NpcSpawnOption`: prefab, weight, min, max).
  - Movement sync: `NetworkTransform` (2D position only, Lerp interpolation, unreliable deltas, half floats, threshold 0.01) + `NetworkRigidbody2D`; tick rate 30. NPCs: Server authority, `Mover` only on the host. Players: Owner authority, `Mover` only on the owner. Players and NPCs don't collide physically (`MPPlayer.IgnoreBodies`). Client visual copies of projectiles burst on a likely hit at once (`MPMatch.LooksHittable`), and the host's later report doesn't burst twice. Every networked prefab must be in `Assets/Settings/Network/LoveShotNetworkPrefabs.asset` (the builder regenerates it).
- **Look:** everything is pink. Team colors, names and the neutral color live in `MPTeams` (Pink, Berry, Coral, Blush); each team also has a symbol shape from the generated `Assets/Settings/TeamStyle.asset` (`TeamStyle.SymbolOf`), used for player emblems, heart-style projectiles, NPC team badges and HUD/lobby swatches. Art is inked cartoon style (thick dark outline baked into the tintable sprites as `InkShade`, cel shading, paper grain, slight wobble), modeled on the two reference images in the project root. In-game HUD panels deliberately have no background images. Projectile speeds in the builder are multiplied by `ProjectileSpeedScale` (1.5) and lifetimes divided by it; the weapon assets were scaled once by hand-run script because the builder never overwrites them.
- **Scenes and prefabs are generated** by `Assets/Editor/LoveShotBuilder.cs` (sprites, menu, shared helpers) + `LoveShotBuilder.Multiplayer.cs` (networked prefabs, lobby, arena, HUD) + `LoveShotBuilder.Art.cs` (procedural inked art: toon sprites, team symbols, faces, candy blocks, paper floor, backdrop; `AddCharacterBody` builds Shadow + Rig/Body/Shine) (menu **LoveShot → Rebuild Arena + Menu**): `Assets/Scenes/MainMenu.unity` (build index 0), `Assets/Scenes/MPLobby.unity` (1), `Assets/Scenes/MPArena.unity` (2), `Assets/Prefabs/` and `Assets/Prefabs/Multiplayer/`. **Rebuilding overwrites the three scenes, all prefabs and generated sprites**, so put tuning that must survive into the builder. Arena size: `MPHalfWidth/MPHalfHeight` in the multiplayer builder.

## Conventions
- Private `[SerializeField]` fields with `Min`/`Range`/`Tooltip` for every tunable value; no public fields.
- Clients send inputs/requests and their own player's position (validated by the host's movement budget); the host decides hits, capture, ownership, scores and timers. Validate RPC senders (`InvokePermission = RpcInvokePermission.Owner` or check `RpcParams.Receive.SenderClientId`).
- Gameplay `Update`s check `MPMatch.InProgress`.
- Fully qualified uGUI types (`UnityEngine.UI.Image`). Use TMP for text; never set TMP outline/material properties from editor code, because that changes the shared font material.
- Match the existing comment style: a short header comment per class, comments only where the reasoning isn't obvious.

## Working with the Editor (Unity CLI + Pipeline package)
- Drive the live Editor with `unity command ... --project-path "C:\Users\User\Pink Game"`. Never hand-edit `.unity`/`.prefab` YAML.
- Check compiles with `unity recompile --project-path ...`, then run `unity status --until-ready` (the connection drops during domain reload).
- For `script eval` code, put C# in a quoted heredoc variable: a `'` char literal inside single-quoted bash breaks the command.
- Before Play-mode tests: `unity command editor set_auto_tick` and `unity command editor.playmode set_run_in_background` (otherwise the game freezes at frame 1 while the Editor is unfocused). Wait on time with `job wait` (`op` is `greaterThan`, not `gt`).
- Test pitfalls already hit: a match ends after 180s (and early once every player is on one team), teleports can land inside obstacles (the arena has interior cover walls), and moving targets dodge scripted shots.
- Screenshots don't include Screen Space Overlay canvases. To see the HUD or menu, switch the canvas to `ScreenSpaceCamera` at runtime (never save that).
- Real-input path: simulate keys with `InputSystem.QueueStateEvent(Keyboard.current, new KeyboardState(Key.D, Key.Space))`, and queue an empty `KeyboardState` to release them. Click menu buttons with `ExecuteEvents.Execute(button, new PointerEventData(EventSystem.current), ExecuteEvents.pointerClickHandler)`.
- After Play mode, `MainMenu.unity` can show as dirty (layout recalculation only). The builder refuses to run on a dirty scene, so reopen it without saving first.
- **Multiplayer testing:** Multiplayer Play Mode clones are activated through internal API by reflection: `Unity.Multiplayer.PlayMode.Editor.MultiplayerPlaymode.PlayerTwo/Three/Four` (in assembly `UnityEditor.MultiplayerModule`) → `UnityPlayer.Activate(out ActivationError, List<string>)` / `Deactivate`. `unity command list_instances` lists them; target a clone with `--project-path "<project>\Library\VP\<vpId>"` (`--instance` isn't accepted by these commands). Entering Play in the main Editor starts Play in the clones. Clones read `ProjectSettings` from disk and need a restart after build-settings changes. Clone game views are tiny, so take screenshots from the main Editor.
- **Never edit scripts while a multiplayer Play session runs:** the Editor's domain reload killed the host's NetworkManager mid-match once.
- Simulated mouse input is unreliable in clones (real OS mouse events override it). Simulated keyboard input only reaches one clone at a time. For movement and shooting tests, set the clone's `MPPlayer.Local.enabled = false` and invoke its private `OwnerTick(move, aim, fire)` by reflection (each call fires at most once; move input persists until the next call). Count projectiles per machine with an `Application.onBeforeRender` watcher stored via `AppDomain.SetData`, since shots can end before the next eval. `GetInstanceID()` doesn't compile in `script eval`.
- In `script eval`, call `SessionOptionsExtensions.WithRelayNetwork(options)` statically (extension `using`s aren't available). `using` directives aren't accepted at all: fully qualify types (`LoveShot.Multiplayer.MPMatch`). LINQ works.
- **Restart MPPM clones after every rebuild or script change** (Deactivate, then Activate): their asset database is read-only, and after the main Editor rewrites assets they hang ("Asset Database is set to Read Only, but it has found out-of-date assets"; `script eval` times out). Deactivate them before editing, reactivate when ready to test.
- Pass clone paths to the CLI with forward slashes (`--project-path "C:/Users/User/Pink Game/Library/VP/<vpId>"`); backslash escaping inside bash strings kept going wrong.
- Multiplayer test helpers that worked: `MPMatch.ApplyLove(target.Capture, creditSlot, power, fromPlayer)` for deterministic hits; `MPPlayer.ServerEquip(index)`; teleport by setting both `Rigidbody2D.position` and `transform.position`; spawn test NPCs from `MPMatch.npcTypes` via reflection and freeze them with `RigidbodyConstraints2D.FreezeAll`. Two client RPCs sent in the same eval arrive in the same host frame (so "fire then stop" fires nothing).
- Git: the repo was created 2026-10-29 with a Unity `.gitignore`; checkpoint commits: `4869fca` = pre-multiplayer, `024c638` = Update 4 (multiplayer FFA), `ce98e98` = Updates 5+6 (last version with single player).
